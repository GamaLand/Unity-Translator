# UnityTranslator 使用指南

## 安装与语言

在 Windows x64 上，将应用 ZIP 中的**全部文件**解压到单独的文件夹，然后运行
`UnityTranslator.exe`。打包版不需要安装 Python。从源码运行：

```powershell
uv sync --locked --extra ui
uv run --extra ui unitytranslator gui
```

界面默认使用英语。**Help** 旁的 **Language** 菜单提供八种语言，选择后在下次启动时生效。
界面语言不会改变项目的源语言和目标语言。

## 翻译流程

1. **项目：**选择游戏文件夹和另一个独立的项目文件夹，并设置语言代码。
   使用“打开现有项目”继续之前的工作。
2. **文本：**运行只读兼容性扫描，选择支持的数据源，然后提取文本。
   文本提取和游戏内安装的支持情况分别检查。
3. **模型：**自行启动 LM Studio 或 llama-server 并加载模型。输入本地服务器地址和模型标识，
   测试连接。应用不会自动启动服务器或加载模型。
4. **术语表：**按需添加保留名称、首选译法和各类别的风格规则。
5. **翻译：**先运行具有代表性的试译并检查结果，再开始批量任务。
   根据服务器性能选择 1–16 个并行请求。最小化窗口不会停止翻译。
   暂停会停止发出新请求并等待正在执行的请求；取消会中断客户端任务。
6. **审校：**对照原文与译文，修改、保存后再明确批准。自动保存草稿并不表示批准。
   按页批准只影响该页选中的合格记录。“批准全部翻译”需要两步确认：先查看数量和警告，
   勾选确认；再准确输入界面显示的短语并点击最终按钮。两个步骤都可以取消。
   有草稿或格式错误的记录会被排除；如果预览列表发生变化，整个操作会停止，不会部分批准。

## 备份、安装与分享

在导出页面生成 JSON 或项目数据备份，备份应保存在游戏目录之外。
对于支持的游戏，请先关闭游戏，在应用到游戏页面准备安装方案，检查新增文件后另行批准安装。
随后自行启动游戏，检查字符、排版和翻译含义。游戏内应用仍属实验性功能。

通过原安装项目删除新增文件。不要直接覆盖或删除冲突的 `winhttp.dll`、`doorstop_config.ini`，
也不要重置原始文件清单。应打开旧项目，按所有权和哈希验证结果卸载。
详见[开发者修复指南](../docs/development.md)。

可分享 ZIP 包含已批准译文和所需运行组件。接收者解压后运行 `Kur.cmd`，选择匹配版本的游戏目录；
`Kaldir.cmd` 只删除属于该包且未修改的文件。接收者不需要模型或 UnityTranslator。
请保留随附的许可证和源码材料。并非所有 Unity 游戏均受支持，自动检查不能保证翻译质量。
部分技术诊断信息会保留原始语言。


游戏翻译的源语言和目标语言与界面语言相互独立。日语使用 ja，意大利语使用 it，巴西葡萄牙语使用 pt-BR，也可输入其他语言代码。源语言必须存在于游戏中；缺失或存在歧义的语言列会被拒绝。模型必须支持所选语言对。现有项目的语言、批准记录和自定义风格保持不变；请检查旧的特定语言风格规则。分享前请用小型补丁检查字体、从右到左的布局和复数形式。英语也可以作为目标语言。
