# UnityTranslator 使用指南

## 已验证的对白上下文

高级模型设置中的**使用已验证的相邻对白**为可选功能，默认关闭。在支持的 Ren’Py 片段中，它按原文顺序显示，并提供目标前后各最多两句原文作为参考。选项、条件、跳转、调用、未知语法及文件边界会截断窗口；翻译模板仅连接同一块内的对白。Unity 术语表及顺序未经证实的来源仍单独翻译。审核页会显示参考原文，请求预算可能减少参考句数。更改模式需要匹配且已审核的试译。已有任务、译文、草稿和批准均保留；不保证译文更自然。

## 安装与语言

在 Windows x64 上，将应用 ZIP 中的**全部文件**解压到单独的文件夹，然后运行
`UnityTranslator.exe`。打包版不需要安装 Python。从源码运行：

```powershell
uv sync --locked --extra ui
uv run --extra ui unitytranslator gui
```

界面默认使用英语。**Help** 旁的 **Language** 菜单提供八种语言，选择后在下次启动时生效。
界面语言不会改变项目的源语言和目标语言。

## 翻译流程

1. **项目：**选择游戏文件夹和另一个独立的项目文件夹，并设置语言代码。
   使用“打开现有项目”继续之前的工作。
2. **文本：**运行只读兼容性扫描，选择支持的数据源，然后提取文本。
   文本提取和游戏内安装的支持情况分别检查。
3. **模型：**自行启动 LM Studio 或 llama-server 并加载模型。输入本地服务器地址和模型标识，
   测试连接。应用不会自动启动服务器或加载模型。
4. **术语表：**按需添加保留名称、首选译法和各类别的风格规则。
5. **翻译：**先运行具有代表性的试译并检查结果，再开始批量任务。
   根据服务器性能选择 1–36 个并行请求。最小化窗口不会停止翻译。
   暂停会停止发出新请求并等待正在执行的请求；取消会中断客户端任务。
6. **审校：**对照原文与译文，修改、保存后再明确批准。自动保存草稿并不表示批准。
   按页批准只影响该页选中的合格记录。“批准全部翻译”需要两步确认：先查看数量和警告，
   勾选确认；再准确输入界面显示的短语并点击最终按钮。两个步骤都可以取消。
   有草稿或格式错误的记录会被排除；如果预览列表发生变化，整个操作会停止，不会部分批准。

## 备份、安装与分享

在导出页面生成 JSON 或项目数据备份，备份应保存在游戏目录之外。
对于支持的游戏，请先关闭游戏，在应用到游戏页面准备安装方案，检查新增文件后另行批准安装。
随后自行启动游戏，检查字符、排版和翻译含义。游戏内应用仍属实验性功能。

通过原安装项目删除新增文件。不要直接覆盖或删除冲突的 `winhttp.dll`、`doorstop_config.ini`，
也不要重置原始文件清单。应打开旧项目，按所有权和哈希验证结果卸载。
详见[开发者修复指南](../docs/installation.md)。

可分享 ZIP 包含已批准译文和所需运行组件。接收者解压后运行 `Kur.cmd`，选择匹配版本的游戏目录；
`Kaldir.cmd` 只删除属于该包且未修改的文件。接收者不需要模型或 UnityTranslator。
请保留随附的许可证和源码材料。并非所有 Unity 游戏均受支持，自动检查不能保证翻译质量。
部分技术诊断信息会保留原始语言。


游戏翻译的源语言和目标语言与界面语言相互独立。日语使用 ja，意大利语使用 it，巴西葡萄牙语使用 pt-BR，也可输入其他语言代码。源语言必须存在于游戏中；缺失或存在歧义的语言列会被拒绝。模型必须支持所选语言对。现有项目的语言、批准记录和自定义风格保持不变；请检查旧的特定语言风格规则。分享前请用小型补丁检查字体、从右到左的布局和复数形式。英语也可以作为目标语言。

## Krypta FM

对于匹配版本的 Krypta FM，请选择源语言 `en`、目标语言 `tr`。配置第 2 版涵盖 34 个 TextAsset 和一张日志表中的 449 个字段；另有两个来源及其他界面或图片文字不在范围内。现有标识和批准记录会保留。

审阅并批准译文后，关闭游戏，在“应用到游戏”中检查新增 `winhttp.dll` 与 `doorstop_config.ini` 的计划。实验性运行时保留在独立项目中，不替换原始游戏文件；请通过同一项目移除新增文件。文本导出不是安装包，可分享的安装 ZIP 也支持匹配的 Krypta en→tr 版本。接收者运行 Install.cmd，审阅文件计划并输入 INSTALL；Uninstall.cmd 只移除未修改且属于该包的新增文件。此便携组合已进行合成测试，单独的游戏内验证仍待完成。已观察启动/菜单、设置、进入游戏、暂停及字幕。其他界面、语言切换和排版需手动检查；过长的设置标签可能与说明文字重叠。

在高级模型设置中，可选择关闭 LM Studio 请求的模型推理，为翻译保留更多输出 token。是否支持取决于已加载的模型和服务器；不支持的选项可能使任务停止。默认值和服务器全局设置保持不变。

## Ren'Py 翻译

在文本页选择引擎并扫描。选择一个 `game/tl/<语言>/*.rpy` 文件会读取整个语言文件夹。
原始 `.rpy`、已验证的 `_ren.py` 和含源码的 RPA-3.0 归档依据与 Ren'Py 8.1.2、8.3.6
比较过的源码行为契约进行检查；仅有版本号不能获得支持。支持大型集合及互不重叠的
独立文件和归档；路径或源码基本名称冲突时会拒绝读取。支持带角色属性和临时 `@` 属性的
单行对白、`nointeract`、显式 `_()` 键和菜单文本。菜单对白必须位于选项之前，不能与标题混用。
voice/nvl 组、多行对白、动态文本、只有编译文件的输入和图片文字仍不受支持，请检查报告的排除项。
提取期间不会执行游戏代码。大型导出可能拆成多个编号文件，请完整保留整个导出目录。

安装 ZIP 仍仅支持 Ren'Py `8.1.2.23090503`；私有仓库、AI 工具或凭据元数据会阻止副本打包。

使用现有的模型、试译、草稿和人工审核流程。模板中的旧译文仅在历史记录中只读显示。
人工批准后，明确输入目标语言的 Ren'Py 标识符，例如 `turkish`；语言代码不会自动转换。
请先完成或丢弃草稿。原生导出只在项目中准备文件；同一全局键存在冲突的已批准译文时会停止导出。

**创建 Ren'Py 安装 ZIP** 为根目录仅有一个游戏 EXE 的匹配版本打包已批准的译文。在游戏外解压 ZIP，运行 `Install.cmd`，只选择一次原始游戏目录，审核计划后输入 `INSTALL`。不复制整个游戏，也不替换已有文件；遇到冲突会停止。仅添加翻译、`Play-Translated.cmd` 和少量所有权记录，因此无需备份原始文件。

游戏目录中的 `Play-Translated.cmd` 选择翻译语言。使用正常存档；运行游戏仍可能更新存档、缓存、日志和字节码。卸载不会恢复旧进度。

保留 ZIP 以运行 `Remove.cmd`。关闭游戏并选择同一目录。只移除收据中未修改的自有添加文件，保留修改过、有链接或未知的文件及审核记录。若 Ren'Py 生成了翻译 `.rpyc` 文件，卸载会在删除任何文件之前停止：请只手动检查/移除列出的翻译旁文件，然后重试，不要删除其他游戏 `.rpyc`。旧 ZIP 继续使用原来的完整副本方式。

命令行：`export-renpy-zip --game ... --project ... --language turkish`。字体、布局和其他场景仍需检查。

如果试译报告仍显示任务运行中，请在任务停止后刷新报告。当所有必要样本均已尝试且存在已完成结果时，也可以评估已取消的试译。保存评估允许在相同设置和源内容下进行批量翻译，但不会批准译文。

评估试译后，保存的术语表/风格修改会应用于新请求，无需重新试译。正在处理的请求按原规则完成，已有译文不变。请检查受影响的记录，并在需要时手动重新翻译。“使用已评估的试译设置”只恢复模型和生成设置，保留当前保存的术语表/风格。

在检查页中，“重新翻译本页记录”将当前筛选页中最多200条可见记录按当前模型设置和已保存的术语表/风格加入共用翻译队列。需要与设置匹配的已评估试译。草稿和正在处理的记录除外。已批准文本保持选中，新候选译文显示在历史中。随后打开翻译选项卡显示进度。

在审核中，**批量操作**可批准与原文完全相同的非空译文，或将空译文重新设为待处理。两项操作都覆盖符合当前筛选条件的所有页面，确认前会显示数量和示例。若需覆盖整个项目，请清除筛选条件。草稿、排队或处理中的记录以及已批准记录会被排除。原文副本仍可能是未翻译的句子，批准须由您明确决定。重新设为待处理会保留历史且不发送模型请求；之后在翻译中按现有试译审核要求启动批量任务。

将空译文重新设为待处理时，允许包含已暂停任务中的排队记录。预览会显示数量；由于工作版本改变，恢复旧任务时会跳过这些旧条目。任务和尝试历史会保留。其他排队或处理中的条目仍会阻止操作；被排除的匹配记录会与无匹配记录分别提示。
